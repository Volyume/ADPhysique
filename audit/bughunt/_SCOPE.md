# Adversarial bug / crash / security hunt — SHARED SCOPE
VOLYUME is a LIVE production app (Expo SDK 54, RN 0.81, JS, offline-first SQLite+SQLCipher, Supabase EU-Dublin) with real paying users. Your job in THIS phase is to BREAK it and HACK it on paper: find every real crash, correctness bug, data-loss path, race, and security hole. Be hostile and specific. This is authorised defensive security testing of the founder's own app.

## RULES
- **READ-ONLY. Do NOT edit any source.** This is the hunt phase; fixes come later after founder triage.
- **Reproduce before you report.** Every finding must be traced to specific code with a concrete trigger (exact inputs/state to wrong output, crash, leak, or data loss). If you cannot construct the trigger, drop it. No speculative "might be an issue" noise.
- **Severity:** `blocker` (crash on a real path / security hole / data loss / safety-invariant leak / privilege escalation) / `major` (broken feature, wrong result, recoverable crash) / `minor` (edge-case, cosmetic-correctness).
- **Note the fix seam but flag sensitivity.** For each finding give the minimal fix, AND tag it `SAFE-FIX` (clear defensive guard in ordinary code) or `FOUNDER-DECISION` if the fix would touch any of: ED-safety (`nutritionEngine.js`, `edPatternDetector.js`, `wellbeing.js`, `weeklyCoach.js`, `coachApply.js`, calorie floors, calm/suppression), billing/payments, the deterministic coaching engine's outputs, consent/GDPR/Article 9, the DB schema or a Supabase migration, or anything where the fix changes behaviour or has a tradeoff.

## WHAT TO HUNT (apply the ones relevant to your assigned surface)
- **Crashes:** null/undefined dereference, unguarded array/object access, unsafe destructuring of async/nullable data, `.map`/`.find` on possibly-undefined, `JSON.parse` without try/catch, number parsing to NaN then propagated, division by zero, out-of-range indices, missing empty/loading/error states, `setState` after unmount, unhandled promise rejections in effects/handlers, missing `await`, throw in a render path.
- **Correctness / data:** off-by-one, floating-point rounding, timezone / local-day (`dayKey`) boundary bugs, week-start (Monday) bugs, DST, sort instability, stale cache, wrong Free/Pro branch, wrong unit conversion, transaction gaps (delete-then-insert without a wrapper), sync conflict / last-write-wins data loss, migration non-idempotency, watermark/queue races, sign-out wipe gaps, offline-then-online reconciliation.
- **Security / hack-it:** SQL injection (raw string interpolation into SQL; scrutinise the food FTS `toFtsMatch` and any `execAsync`/template SQL), SSRF / unsafe fetch (recipe-URL import, live OFF/USDA), deep-link and route-param injection (partner codes, `route.params`), unvalidated external input (barcode, OCR text, custom food, recipe JSON-LD), RLS gaps (can user A read/write user B's rows?), SECURITY DEFINER RPC privilege / missing auth checks, client-only trust (a gate enforced only in the client that the server does not re-check), secrets/keys committed in code, PII to Sentry/logs/telemetry, insecure storage of the DB key or tokens.
- **Safety invariants (the app's own inviolables) failing under adversarial input:** any path where an ED flag / SCOFF / calm read fails OPEN, a calorie floor can be bypassed, a share card or partner payload leaks raw body/weight/food/location/name data, the deterministic engine uses `Math.random()`/`Date.now()` in a way that breaks reproducibility, or free bypasses a Pro gate at the data layer.

## OUTPUT (per agent)
- `audit/bughunt/<class>-findings.md`: findings ranked most-severe first. For each: `[SEVERITY][SAFE-FIX|FOUNDER-DECISION] file:line — one-line issue`, then trigger, then failure, then minimal fix. End with a one-line count by severity.
- Do NOT run the test suite to "fix" anything (read-only). You MAY run targeted greps and read tests to confirm a bug is not already guarded. NO git commits.
