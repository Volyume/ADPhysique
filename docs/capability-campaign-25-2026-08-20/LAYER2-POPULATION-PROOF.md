# LAYER 2 POPULATION-BY-POPULATION PROOF (reconciliation 2026-08-21)

Answers the founder's reconciliation area 3: for every one of the 20
condition profiles, the correct product-response classification with
evidence, and proof that every claimed layer is PRESENT in the product.
Classifications per the reconciliation order:

- **A** capability-only is the correct complete response
- **B** capability + condition-specific guidance
- **C** capability + population collection (function-first plans the
  profile points at)
- **D** capability + accessibility response
- **E** external/clinical only (the load-bearing answers stay with the
  professional; the profile encodes the boundary)

A profile can genuinely be several. "Present" is proven by module
fields that ship and render (detail surface: education, setup, sources,
"Plans that often fit" — TrainingConsiderationsScreen.js:139-142) and
by `directorySchema.test.js`, which pins every `familyRelevance` name
to a REAL seeded plan (no dead pointers possible).

## The mechanism behind every C (read this first)

Population collections are served FUNCTION-FIRST: each profile's
`familyRelevance` names shipped capability-family plans, and the same
plans surface through computed compatibility the moment the profile's
questions are answered ("Fits how you train" chips). Condition-NAMED
shelf labels ("Wheelchair strength") remain withheld behind the
recorded gates (GC-D5: dossier + CLIN + LEG-23/Q9 + user validation) —
which is the amendment's own §5/§7/§10 demand, not a shortfall. The
amendment's §5 obligation reads "routines, collections OR guidance";
guidance ships for all 20, collections ship function-first for all
that need them.

## The three research-supportable labelled populations (SCI, MS, Parkinson's)

R5's verdict: a curated LABELLED routine is plausibly supportable, with
dossier, ONLY for these three. State of each layer today:

- Research: banked and cited (R5 + R7, live-verified).
- Dossier: built (DOSSIER-SCI/MS/PARKINSONS, incl. required validation
  and review per population).
- Function-first plans: shipped and pointed at by each profile.
- Directory guidance: shipped with quotes from the population's own
  authorities.
- The LABEL: withheld behind the amendment's own gates (§7 dossier
  process incl. expert review, §10 marketing gate, §11 user
  validation) plus counsel Q9. This is the responsible outcome the
  reconciliation order allows ("If capability-only is genuinely the
  responsible outcome, record why") — with the stronger note that what
  ships is NOT capability-only: guidance and collections exist,
  function-first; only the population NAME on a shelf waits for the
  external gates.

## Populations where capability-led IS the whole answer (recorded why)

- Visual, hearing, learning disability: the disability affects app
  access, not programming — amendment §6's own category law ("solve
  the correct problem"). Programming forks would be invented, not
  evidence-led.
- Wheelchair users: not one research population (R5); the profile's
  job is honest routing plus shoulder-balance guidance.
- Short stature: no training guideline exists (stated in-profile);
  setup adaptation is the genuine need.
- Everything else ships B-level guidance rather than population
  routines because the research explicitly does not template
  parameters (CP meta-regression, stroke, amputation — R5 central
  finding), and pretending otherwise would be the §7 pseudo-medical
  failure the amendment bans.
