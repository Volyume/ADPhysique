## TOP RISKS

1. **Play targetSdk 36 deadline is 2026-08-31 — 20 days out — and the repo is pinned to 35. VERDICT: FAIL.** No app update can be submitted to Google Play from 2026-08-31 without API 36 (`https://developer.android.com/google/play/requirements/target-sdk`). An extension to 2026-11-01 is available and should be requested now as insurance, in parallel with doing the work.

2. **The targetSdk-36 bump drags in Android 16's adaptive-layout change, which ignores the app's portrait lock on ≥600dp screens. VERDICT: ACTION-NEEDED, founder fork.** 82 screens have never been laid out for tablet-width landscape. Google's `PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY` opt-out is documented and legitimate but expires at API 37. Options — (a) ship the opt-out with the bump, (b) do the large-screen work first — must go to the founder as a choice, not be pre-decided.

3. **iOS Universal Links are entirely unconfigured while the app and its partner-invite feature depend on them. VERDICT: FAIL.** No `associatedDomains` anywhere in the repo, yet `RootNavigator.js:749` registers `https://volyume.app` and `partners/link.js:19` mints `https://volyume.app/partner/<CODE>` invites. Every invite tapped on an iPhone today opens Safari instead of the app. Android has verified App Links for the same host, so this is a live one-sided breakage. Requires an entitlement + an AASA file + a new build.

4. **No Terms of Use / EULA link anywhere in the app, on a paywall selling auto-renewable subscriptions. VERDICT: ACTION-NEEDED.** Grep for `Terms of Use`, `EULA`, `apple.com/legal` across `src/` returns zero hits. The paywall's only legal button is a feature-downgrade explainer carrying a misleading `accessibilityLabel="Subscription terms"`. This is a routine App Review 3.1.2 rejection trigger and the privacy policy is also not linked from the paywall.

5. **`runtimeVersion: appVersion` plus `EAS_SKIP_AUTO_FINGERPRINT: "1"` means a native change can silently ship a mismatched EAS Update to live paying users. VERDICT: ACTION-NEEDED.** Expo documents the failure mode verbatim: "if you forget to bump the app version when changing the native runtime, then you'll have a runtime version mismatch." Every fix in risks 1-3 is a native change. Hard rule for the rest of this campaign: bump `expo.version` before publishing any update after touching `app.json` native config, plugins, `expo-build-properties`, or a native dependency.

6. **Xcode 26 / iOS 26 SDK has been mandatory for App Store uploads since 2026-04-28, and `eas.json` pins no build image. VERDICT: ACTION-NEEDED / partly UNVERIFIED.** Expo SDK 54 supports Xcode 26, so the toolchain is fine — but the production profile takes whatever the EAS default macOS image carries.
