## Lead rulings (D33) (ruling 1 SUPERSEDED above; 2 to 6 stand)

1. **Explicit opt-in only.** Volyume is free, so the PECR soft opt-in (contact
   details obtained in the course of a sale) does not cover members. A member
   receives news, offers or surveys only after saying yes in the app. Off by
   default, never pre-ticked. Every email has a one-click unsubscribe.
2. **Wellbeing suppression, fail closed.** Nobody is emailed while
   `public._community_consistency_withheld(uid)` is true (open ED flag OR calm
   mode; both arms fail closed, migrate_180). Offer copy never uses weight,
   body or outcome framing (marketing CLAIMS-STANDARDS) and never an em dash.
3. **Consent proof.** Every change is appended to an event table with the
   exact wording version and where it was given (settings, prompt, email).
4. **Re-consent clears an email opt-out.** Turning the switch on again in the
   app is a fresh, explicit yes, so it removes that user's opt-out row.
5. **Admin sign-in without Supabase Auth settings.** The private page signs in
   with a one-time link the edge function emails to an address in
   `marketing_admins` (15 minutes, single use), exchanged for a 12-hour signed
   admin session. No dashboard redirect settings are needed.
6. **The link secret is generated by the migration** into a service-role-only
   table, so the only secret the founder sets is `RESEND_API_KEY`.

## 1. Cloud schema: `supabase/migrate_198_member_email.sql`

Header per CLAUDE.md (purpose, applied status WRITTEN NOT APPLIED, safe to
re-run, rollback). Additive and idempotent. RLS on every table.

- `member_email_consent` (user_id uuid PK REFERENCES auth.users ON DELETE
  CASCADE, consented boolean NOT NULL DEFAULT false, wording_version text NOT
  NULL, source text NOT NULL CHECK (source IN ('settings','prompt','email')),
  consented_at timestamptz, withdrawn_at timestamptz, updated_at timestamptz
  NOT NULL DEFAULT now()). Owner SELECT only. No client INSERT/UPDATE.
- `member_email_consent_events` (id uuid PK, user_id uuid REFERENCES
  auth.users ON DELETE CASCADE, consented boolean NOT NULL, source text NOT
  NULL, wording_version text NOT NULL, created_at timestamptz NOT NULL DEFAULT
  now()). No client access.
- RPC `member_email_set_consent(_consented boolean, _source text,
  _wording_version text) RETURNS jsonb`, SECURITY DEFINER, pinned
  search_path, authenticated only (not anon). Uses auth.uid(); validates
  source IN ('settings','prompt') and wording_version length 1..40; upserts
  the consent row (consented_at on a yes, withdrawn_at on a no), appends an
  event, and on a yes deletes the user's `marketing_email_optout` row.
  Returns { consented, updated_at }.
- RPC `member_email_get_consent() RETURNS jsonb` (authenticated): the caller's
  row or { consented: false }.
- `member_email_campaigns` (id uuid PK DEFAULT gen_random_uuid(), subject text
  NOT NULL CHECK (char_length 1..150), preheader text CHECK (<= 200), body
  text NOT NULL CHECK (char_length 1..20000), button_label text CHECK (<= 40),
  button_url text CHECK (button_url IS NULL OR button_url LIKE
  'https://%'), survey_id uuid NULL REFERENCES member_surveys, status text NOT
  NULL DEFAULT 'draft' CHECK (status IN ('draft','sending','sent','partial')),
  recipient_count int, sent_count int NOT NULL DEFAULT 0, failed_count int NOT
  NULL DEFAULT 0, created_by text, created_at, updated_at, sent_at).
- `member_email_sends` (campaign_id uuid REFERENCES member_email_campaigns ON
  DELETE CASCADE, user_id uuid REFERENCES auth.users ON DELETE CASCADE, status
  text CHECK (status IN ('sent','failed')), provider_id text, error text,
  sent_at timestamptz, PRIMARY KEY (campaign_id, user_id)).
- `member_surveys` (id uuid PK, title text CHECK (1..120), intro text CHECK
  (<= 1000), questions jsonb NOT NULL, status text NOT NULL DEFAULT 'draft'
  CHECK (status IN ('draft','open','closed')), created_at, updated_at).
  Question shape (validated in the edge function AND by a CHECK on
  jsonb_typeof = 'array' and array length 1..20): `{ id: 'q1'..., type:
  'single'|'multi'|'text', prompt (1..300), options: [1..10 strings of
  1..120] for single/multi, required: boolean }`.
- `member_survey_answers` (id uuid PK, survey_id uuid NOT NULL REFERENCES
  member_surveys ON DELETE CASCADE, user_id uuid NULL REFERENCES auth.users ON
  DELETE CASCADE, answers jsonb NOT NULL CHECK (pg_column_size(answers) <=
  20000), created_at). UNIQUE (survey_id, user_id) (nulls distinct, so
  anonymous answers are allowed).
- `member_email_admin_logins` (nonce text PK, email text NOT NULL, expires_at
  timestamptz NOT NULL, used_at timestamptz).
- `member_email_config` (key text PK, value text NOT NULL): seeded ON CONFLICT
  DO NOTHING with `link_secret` = encode(gen_random_bytes(32),'hex').
- `member_email_audience() RETURNS TABLE(user_id uuid, email text)`, SECURITY
  DEFINER, service_role only: auth.users joined to consent (consented =
  true), email confirmed and not null, NOT EXISTS an opt-out row for that
  user_id or that email (case-insensitive), AND NOT
  public._community_consistency_withheld(u.id).
- Every admin table: no grants to anon or authenticated; service_role all.
- Acceptance block at the end (as recent migrations do): the RPCs exist with
  the right executability, RLS is on, the audience function is not callable
  by authenticated.

## 2. Edge functions (Deno, `supabase/functions/`)

Shared `_shared/memberEmail.ts`: HMAC-SHA256 tokens
`base64url(json).base64url(sig)` with the `link_secret`; email rendering
(HTML + plain text) from the campaign fields; the house copy lint (refuse an
em dash in subject, preheader, body or button).

Email format: From `Volyume <news@volyume.app>`; Reply-To from env
`MEMBER_EMAIL_REPLY_TO` if set; headers `List-Unsubscribe: <https://<project
ref>.supabase.co/functions/v1/member-email-public?action=unsubscribe&t=...>`
and `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. HTML: the wordmark
(https://volyume.app/volyume-wordmark.png), paragraphs, optional button, the
survey button when survey_id is set (link
`https://volyume.app/survey/?id=<survey>&t=<token>`), footer "You are getting
this because you said yes to news from Volyume in the app.
[Unsubscribe](https://volyume.app/email/unsubscribe/?t=<token>)". Body
format: paragraphs split on blank lines, `**bold**`, `[text](https://...)`;
everything else escaped.

### `member-email-admin` (verify_jwt = false; own session)
POST JSON `{ action, session?, ... }`. CORS for https://volyume.app only.
- `request_login { email }`: if the email (lower-case) is in
  `marketing_admins`, insert a nonce (15 min) and email a link
  `https://volyume.app/members/?login=<nonce>`. ALWAYS answer `{ ok: true }`
  (no admin enumeration). Rate limit: at most 5 open nonces per email.
- `exchange { login }`: single use, unexpired → `{ session, email,
  expires_at }`, session = signed `{ e: email, x: exp(12 h), p: 'admin' }`.
- Every other action requires a valid session whose email is STILL in
  `marketing_admins`.
- `overview`: audience count, consent yes count, opt-out count, campaigns
  (latest 50) and surveys (latest 50) with counts.
- `save_campaign { id?, subject, preheader, body, button_label, button_url,
  survey_id }` (drafts only), `delete_campaign { id }` (drafts only).
- `preview { id }` → `{ html, text, subject }`.
- `send_test { id }`: to the signed-in admin's own address only, subject
  prefixed "Test: ".
- `send_campaign { id, expected_recipients }`: refuses unless the live
  audience count equals `expected_recipients` (the page shows the number and
  the founder confirms it). Status 'sending', then Resend batch
  (`POST https://api.resend.com/emails/batch`, at most 100 per call) to every
  audience member without a 'sent' row for this campaign; one row per user;
  per-user unsubscribe and survey tokens; a 429 or provider error records
  'failed' rows and leaves status 'partial'. Calling it again on a 'partial'
  campaign sends only to those not yet sent (idempotent by the PK).
- `save_survey { id?, title, intro, questions }`, `set_survey_status { id,
  status }`, `survey_results { id }` → per-question counts for choices and the
  list of text answers (newest first), plus total responses. `export_survey {
  id }` → CSV text.

### `member-email-public` (verify_jwt = false)
- GET `?action=get_survey&id=` → open surveys only: `{ title, intro,
  questions }`.
- POST `{ action: 'submit_survey', id, answers, t? }`: open survey only;
  answers validated against the questions (ids, types, option membership,
  text <= 2000 chars, required answered); a valid `t` binds user_id (one
  answer per user per survey: a second submit replaces the first); no `t` is
  an anonymous answer.
- POST `{ action: 'unsubscribe', t }` and the one-click POST form body
  `List-Unsubscribe=One-Click` to `?action=unsubscribe&t=`: inserts the
  opt-out row (user_id and email), sets consent false with withdrawn_at, and
  appends a consent event with source 'email'. Idempotent. Answers `{ ok:
  true }` (one-click: 200 with an empty body).
- CORS: https://volyume.app.

Secrets: `RESEND_API_KEY` (founder sets it in the Supabase dashboard,
Edge Functions, Secrets); `MEMBER_EMAIL_REPLY_TO` optional;
SUPABASE_SERVICE_ROLE_KEY and SUPABASE_URL are provided by the platform.

## 3. Website (`public/`, GitHub Pages)

- `public/members/index.html` (noindex, no link from anywhere): sign in with
  email → "Check your email" → the link returns with `?login=` → exchange →
  session in sessionStorage. Then, phone-first:
  - **Overview:** "N members will receive this" (audience), yes count,
    unsubscribes.

    short format hint, optional button label and link, optional survey

  (`?id=&t=`). With no `id`, it keeps the current five-question retention

  `member-email-public` unsubscribe; with the legacy `?u=` it keeps today's

- `public/privacy.html` (and `public/privacy-policy.md`): a section on news

## 4. App (React Native)

- `src/lib/memberEmail/consent.js`: reads and writes the consent through the
  sync layer (components never call Supabase directly): local mirror in
  AsyncStorage `@volyume_member_email_consent_<uid>`, cloud write via the
  `member_email_set_consent` RPC through the existing transport, retried via
  the sync queue when offline (follow the house pattern for small RPC
  pushes). `MEMBER_EMAIL_WORDING_VERSION = '2026-10-17'`.
- Settings: a switch "News and offers by email" with the line "New features,
  the occasional offer and short surveys. You can stop at any time, here or
  from any email." Off by default. Lives with the other communication
  settings (NotificationSettingsScreen or the Privacy area; follow the
  screen that already holds similar choices).
- One prompt, once per account: a calm sheet "Hear about new features by
  email?" with the same line and two buttons "Yes, email me" and "No thanks".
  Shown at most once (stored), only after first run is complete, never on a
  session start that already showed another prompt, never under calm mode or
  an open ED flag (it waits), never in the middle of a workout. "No thanks"
  writes nothing to the cloud; "Yes" writes consent with source 'prompt'.
  New sign-ups see it the same way after onboarding.
- Account deletion and sign-out: nothing extra (the rows cascade with the
  account; the local mirror is cleared with the rest of AsyncStorage).
- The in-app privacy notice text, if the app carries one, gains the same
  short paragraph (privacyTruth guards updated).
- What's new: at the next version bump (founder builds), one line: "You can
  choose to hear about new features by email."
