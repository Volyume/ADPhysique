Workout logger audit · 6 October 2026

The logger today and three ways to rebuild it

Same theme, same tokens, same engine. What differs is the model: what the screen shows, where the entry lives, and how a person moves through a session. The record and the evidence are in docs/audit/workout-logger-audit-2026-10-06/.

Every mockup is drawn with the app's live tokens (charcoal ladder, amber as the one accent, Inter, 16px cards and buttons). Nothing shown needs a new typeface, palette or dependency. The data on the screens is the audit's seeded persona: Upper A, exercise 2 of 6, one warm-up and one working set logged on Barbell Row.

What the logger is today

Current (store build). The elapsed clock is the largest type; the exercise name is small; the two numbers being committed are body size inside 36dp boxes. Amber is spent nine times (steppers, finish, chevron, progress line) and not on the action: Log set is charcoal. Four surfaces nest inside the active card; the warm-up row is the only yellow thing on screen. One exercise and three of its sets are visible; the lower third is empty; the rest of the session is behind a strip that closes itself after five seconds.
What the code map found underneath (lanes A1 and A2).
  • A planned exercise reaches the logger without its type, load meaning or increment, so a dumbbell lift says "Weight (kg)" not "per hand" and every planned lift steps at the barbell increment.
  • "Shorten session" writes a rest cut to a field no timer reads; "Undo" drops every set logged since.
  • Three different rules count "sets done"; a drop set repeats the badge of the set before it.
  • Android back is cancel or discard; iOS swipe-back leaves the session live; a second start from Train silently overwrites a live session.
  • Nothing about a finished session can be corrected; only a hard delete.
  • A comma keystroke is dropped in the weight box; the whole 7,170-line screen re-renders every second.
These are fixed in the foundation, whichever option is chosen.

Option A · Focus, finished

One exercise at a time, as today, which suits a prescriber: the engine says what the next set is. Every pinned structure law is kept. Everything the person sees is rebuilt: the exercise is the hero, the sets are a table with a previous column, the two live numbers are large, and amber is spent once, on Log set.

Option B · The sheet

The whole session on one scrolling page: every exercise a block, every set a row. This is the model the leading loggers converged on. Volyume's version keeps what the September device verdict was really about: the current row never drifts (the page scrolls to keep it on a fixed stage), rest is a strip, completed work is quiet, the way forward is visible.

The foundation, whichever you choose

  • One way to start a session, with a live-session guard, the readiness sheet where asked, and the programme position attributed correctly from every door.
  • Every exercise reaches the logger as the full library row (type, per-hand or assisted, increment).
  • One count of "sets done" everywhere; drop sets numbered honestly.
  • Back and swipe both leave the session live; Cancel is the only discard; a session returns to the tab it started from.
  • Removing or swapping an exercise with logged sets asks what to do with them; Shorten session either cuts rest or stops saying so; Undo never drops sets.
  • One picker, one filter model, no duplicate adds, proper muscle names.
  • Comma and dot both accepted; an edit can change type and note.
  • Planned sets, load, rep band and rest stored on every set, so the summary and history show planned next to done.
  • A finished session can be corrected: edit, add a missed set, rename, re-date, delete one exercise.
  • The screen split so the clock, the rest strip and the sheet render independently.
  • Copy that states only what the code does; timed and distance sets print as time and distance everywhere.
  • Show the working: a one-tap "why this number" on every served load and rest, on demand, never standing in the row.
  • A change to the current set's load or reps is applied to the remaining unlogged sets, shown as one quiet line with an undo.
  • "Update the routine?" at finish when sets, loads or exercises differed from the plan.

Questions to answer

Q1
The model: A, B or C. C is the lead's recommendation.
Q2
The entry: the in-app number pad, or the steppers as today. C assumes the pad.
Q3
Plate calculator: struck in July (D57, "never revisit"); six of the twelve leading loggers document one (Hevy, Strong, Boostcamp, Alpha Progression, Setgraph, Gymaholic). Reverse, or keep struck.
Q4
RPE or RIR per set: struck (D14, D19); six of the twelve leading loggers document one and three more partially; the engine already stores RIR. Reverse as an optional field off by default, or keep struck.
Q5
Exercise media: none today. Licensed illustrations (a dependency), app-drawn line art over time, or text only.
Q6
Watch logging: a separate campaign. Now, or not in this round.
Q7
The summary's order: numbers first and Community after, or as today.
Q8
Build order: the foundation first (visible fixes within days), then the model; or the model first.
Q9
A session cut short: offer to carry the remaining sets to a planned workout, deciding whether carried sets count toward the week's volume; or keep today's ended-early resolution.
