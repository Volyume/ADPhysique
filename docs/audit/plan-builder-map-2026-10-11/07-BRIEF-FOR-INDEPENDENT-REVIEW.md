# 07 Brief for an independent review (paste this with the map)

You are reviewing the training-plan builder of Volyume, a live bodybuilding app (React Native, offline-first). Attached is a factual map of how it works today, produced from the code and from real plans generated by the code. The founder does not want the previous engineer's opinions; treat the map's descriptions as claims to check against the samples and measurements in it, and prefer the samples and measurements where they disagree with any prose.

Hard constraints you must design within (these are product law, not preferences):
- The coaching engine is deterministic: same inputs, same plan. No AI or randomness at runtime.
- Users have no fixed training days. Sessions run as a rotation, so the next session may be the next calendar day.
- Plans are built per category: general hypertrophy, open bodybuilding, men's physique, classic physique, bikini, wellness, figure, women's physique; 2 to 6 sessions a week; session length 30 to 90+ minutes; equipment from full gym down to bodyweight; up to three focus muscles ("bring up" picks); beginner to advanced.
- Founder rules already given: the standard routine of the category is always kept, and focus picks add on top; nothing is removed to fit the clock (rest is shortened first, then the real length is shown); men's physique trains legs once a week; injury risk from poor structure is unacceptable.

What to produce:
1. For each category and each of 2 to 6 sessions a week: the correct weekly structure as a mainstream evidence-based coach would write it (session names, muscles per session, order), with sources (federation criteria, peer-reviewed volume and frequency research, and named coaches' published programmes). State where the evidence is thin.
2. Per muscle and category: weekly set ranges for an intermediate (minimum to grow, typical, upper), how many sessions a week, and minimum hours between two sessions that train it directly, with sources. Include indirect load (for example chest pressing loading front delts and triceps) and how it should count.
3. Rules a plan must never break, written so a program can check them (for example: no muscle trained directly in two back-to-back sessions; no overhead pressing the day after chest pressing; at most N exercises and M sets a session; per-exercise set caps). Give the reasoning and sources for each.
4. What should win when goals conflict (weekly volume, recovery between sessions, session length, focus picks, category emphasis), as an ordered priority list with reasons.
5. A diagnosis of the current builder using the map's samples and measured issues: what is structurally wrong, which mechanisms cause it, and whether the right fix is to repair the current planner, return to the older generator described in the map, or design a new approach. Be specific about which parts of each are worth keeping.
6. A test plan: the checks that should run against every plan the app can produce before any release.

Format: plain, structured, sources inline. Separate what the evidence supports from your judgement.
