# 25 Phase 8: people already on plans (lead rulings, 2026-10-12)

Authority: `11-BUILD-PLAN.md` phase 8 ("Active plans built by the old planners are rebuilt through the engine at the next session (the existing rebuild mechanism, facts version 2 to 3), keeping their exercises wherever the checks allow. Hand-built plans are left as built and checked; a hard-check failure shows a calm note, never a silent change. The founder's own hand-built plan is untouched."); phase 6 and 7 specs (23, 24). Everything here runs only with `STRUCTURE_ENGINE` on; with it off, behaviour is identical.

## Lead rulings (D33)

**R90 Which plans move.** At the next session (`planRebuild.ensureActivePlanRebuilt`, run()), with the switch on: a GENERATED plan (`classifyPlanKind`) whose facts are not an engine plan (`facts.structure?.version !== 3`) is rebuilt through the engine. The "already current" test becomes `facts.structure?.version === 3` for generated plans (today it is `facts.version === 2`), and a plan whose rebuild state says `done` under the old planner is re-run once: the state record gains `engine: 3`, and only a `done` WITH `engine: 3` counts as current.
**R91 Never moved:** the founder's protected programme (R67, PROTECTED_PROGRAMME_IDS, checked first); authored plans (`facts.kind === 'authored'`, D227); LIBRARY and kit plans (fixed programmes, R79); MANUAL (hand-built) plans; style-pool plans (kettlebell, circuit tags: the engine has no pool).
**R92 Keeping exercises.** The rebuild passes the plan's current exercise names (in their sessions) to the engine as preferred choices (the same channel as `loggedExerciseNames`, highest preference), so a muscle keeps its current exercise wherever the engine's checks allow; a kept exercise is never forced in where the checks reject it. The rebuild note (`planRebuildNote`) lists, in plain words, each exercise kept, swapped (old to new) and added or removed, as it does today.
**R93 Keeping the block.** As today's rebuild: the running block keeps its week (`rebuildPlanKeepingBlockV2`, mode in place), the current and later weeks take the engine's ladder; logged history is untouched; typed counts the person set are kept and served as typed (R76 governs later edits).
**R94 Refusal or question.** If the engine refuses the person's current days and length, or would ask a length or focus question, nothing is rebuilt: the plan keeps serving as it is, the state records `skipped: needs_choice`, and one calm card on Today offers "Update your plan" (the existing PlanUpdate flow, which shows the engine's choices with R83's controls). Never a silent change, never a half-rebuilt plan.
**R95 Hand-built, library and kit plans are checked.** Once per plan version, the general checks (R79: neighbouring sessions, per-session and per-exercise limits, joints) run over the plan as stored; a hard failure shows one calm note on the plan screen naming what it found in plain words ("Chest is trained on two days in a row in Push and Upper. A day between them gives it time to recover."), never a change. Authored plans skip it (their departures are recorded exceptions, D227).
**R96 Safety and reversibility.** Each rebuild runs in one transaction; a failure leaves the plan exactly as it was (state `failed`, retried at most twice, as today). The previous facts are kept under `facts.previous` (one level) so support can see what changed.
**R97 Tests.** For each plan kind: generated plan rebuilt once with exercises kept where allowed; second run is `current`; refusal leaves it untouched and records needs_choice; protected, authored, library, kit, manual and style-pool plans never rebuilt; hand-built plan with a hard fault gets the note and no change; switch off = today's behaviour.
