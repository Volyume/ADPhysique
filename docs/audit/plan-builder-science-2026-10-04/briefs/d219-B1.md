Users can swap exercises as they wish but I don't want users looking and wondering what this exercise actually is."

DO:
1. Add a comment at each move citing D219 and the reason in one line (the evidence-preferred choice per S Q12, or "standard in nearly every commercial gym").
2. New pure module `src/lib/plan/catalogue.js` (no imports outside src/lib/plan and src/lib/exercise; no I/O): the curated catalogue, per muscle, an ordered list of roles exactly as the design's section 4.7 table gives them (first choice, second choice, third only when a session needs it), each role with:
   - `names`: corpus exercise names in preference order. The order encodes the design's tie-break among equivalent variants: the lengthened-position variant first where S Q12 names one, then equipment order barbell, dumbbell, machine, cable. Use these STAPLE names (after step 1): chest flat press 'Barbell Bench Press', 'Dumbbell Bench Press', 'Machine Chest Press'; chest incline 'Incline Dumbbell Press', 'Incline Barbell Bench Press', 'Incline Machine Press'; chest third 'Pec Deck (Machine Fly)', 'Cable Crossover (High to Low)'; back vertical 'Lat Pulldown (Wide Grip)', 'Pull-Up', 'Chin-Up', 'Lat Pulldown (Neutral Grip)'; back horizontal 'Seated Cable Row', 'Chest-Supported Row (Dumbbell)', 'Machine Row (Chest Supported)', 'Barbell Row (Bent Over)', 'Dumbbell Row'; traps 'Dumbbell Shrug', 'Barbell Shrug'; biceps first 'EZ Bar Preacher Curl', 'Preacher Curl (Dumbbell)', 'Preacher Curl Machine', 'Preacher Curl (Barbell)', second 'Barbell Curl', 'Dumbbell Curl', 'Cable Curl', third 'Hammer Curl';    - `credited`: true for a role the design marks "credited from" (front delts, glutes, adductors first choice), so the planner knows the first choice is indirect.
   - `optIn`: true for adductors, forearms, neck, tibialis.
   - `reason`: one plain sentence a person reads in the plan (design section 6, "Each exercise in the plan"), true to S Q12 and F13 and no stronger than the evidence (a D-graded role gets a plain description, never a claimed result), British English, no em dash, no instruction (D204).    - `grade` and `source` (from S Q12 / F13).
   And a pure resolver `resolveCatalogue({ library, profile, loggedExerciseNames })` that returns, per muscle, an ORDERED ARRAY (catalogue order, credited roles left out) of the chosen exercises for the person's equipment profile, each `{ name, exerciseId, role, kind, credits, reason, grade, source, thinKit }`: `kind` is the pool's paramKey for the row (`poolGenerator.deriveParamKey(equipment_category, compound_isolation)`: heavy_compound, mod_compound, machine or isolation), and `credits` is the half credit one set gives each OTHER muscle, from the row's secondary muscles with the same rules as `allocateExerciseVolume` in `src/lib/algorithms.js` (for example `{ triceps: 0.5, front_delts: 0.5 }` for a bench press). Where a profile has NO listed name for a role, propose a fallback list of recognisable COMMON rows for that profile (for example a push-up for chest in the bodyweight profile), marked `thinKit: true`, and list every such fallback in your report for the lead's ruling; never fall back silently and never to NICHE, NEVER_AUTO or SPECIALIST rows (opt-in muscles aside).
