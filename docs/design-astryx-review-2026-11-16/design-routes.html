Volyume · design routes

Three ways to redesign Volyume

The same two screens drawn in each route's style, using Volyume's real content and amber brand. Each concept follows that library's default look, re-skinned in amber, so you can judge the character, not the colours.

Route 1

Volyume building blocks

Keep today's code. Build a small, fixed set of pieces (one primary button, grouped list, prompt row, input field) with checks that stop screens styling things by hand.

Look
Dark charcoal, borderless, amber leads
New packages
None
Change
Gradual, screen by screen
Keeps
Higher-contrast and colour-blind palettes as they are
Route 2

React Native Reusables

shadcn/ui for phones. Components are copied into the repo, so Volyume owns and edits them. Styling moves to NativeWind (Tailwind classes).

Look
Crisp, neutral, hairline borders, compact
New packages
NativeWind, Tailwind, a few small helpers (MIT)
Change
Restyle about 309 files
Keeps
Palettes need rebuilding as Tailwind theme variables
Route 3

Tamagui

A theme engine with a compiler, plus a UI kit. Its "sub-themes" let a whole card take on the amber palette in one line. Grouped list items are a built-in strength.

Look
Soft, layered, tinted surfaces, rounder
New packages
Tamagui core, UI kit and Babel compiler (MIT)
Change
Rewrite components on its primitives
Keeps
Palettes map to its themes fairly directly

How they differ in practice

Route 1

Closest to Volyume today, so least risk to the accessibility work and the safety-related screens. The look is only as good as the building blocks we design, but once they exist every new screen gets them for free.

Route 2

The most widely recognised modern look, and Volyume owns every component file. It is also the most generic: without care it can feel like a web dashboard, and it rewrites how every screen is styled.

Route 3

The most distinctive and the most "app-like" of the three. Sub-themes make tinted states easy. It is the biggest technical change and adds a compiler step to the build.

Routes 2 and 3 are new dependencies, which need your yes under the project rules. Screens keep their wording and their calm-mode and ED-flag behaviour in every route; only the presentation changes.

Drawn in HTML with Volyume's real content. Route 2 follows shadcn/ui "new-york" defaults (neutral greys, hairline borders, 8px buttons, square checkboxes). Route 3 follows Tamagui's default look (Radix-style colour scales, sub-themed surfaces, grouped list items). Both are re-skinned in amber. These are illustrations of each library's character, not output from the libraries themselves.
