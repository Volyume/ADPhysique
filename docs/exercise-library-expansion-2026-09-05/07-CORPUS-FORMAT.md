# 07 — Corpus format and integration spec (EL-14 to EL-20)

Implementation spec for the structured corpus. Authority: `05-DECISIONS.md`.

## 1. Modules

```
src/lib/exerciseCorpus/
  index.js          export const CORPUS (all families concatenated, source order)
                    export const CORPUS_BY_NAME (Map name -> entry)
                    export function corpusEntryToSeedRow(entry) -> the object
                      seedExercises' insert path expects (see 3)
                    export const FAMILY_NAMES
  families/
    barbell.js dumbbell.js cable.js machine.js smith.js bodyweight.js
    band.js suspension.js kettlebell.js landmine.js carries.js power.js
    specialty.js medicine_ball.js sled.js
```
Every family module: `export default [ /* entries */ ];` with a header
comment (family, conventions, sources policy). Entries are plain object
literals, one per exercise, alphabetical within a section, sections by
movement. Pure: no imports except constants from `./vocab.js`.

`vocab.js` exports the closed enums (muscles, equipment, patterns,
subregions per muscle, tiers, laterality, loadCharacter, exerciseType,
demand axes) used by the guard.

## 2. Entry shape

```js
{
  name: 'Kettlebell Swing (Single-Arm)',      // canonical, immutable
  primaryMuscle: 'glutes',
  secondaryMuscles: ['hamstrings', 'back'],
  equipment: 'kettlebell',                    // coarse enum incl. band, suspension,
                                              // landmine, medicine_ball, sled
  movementPattern: 'hinge',
  compound: true,
  repMin: 10, repMax: 20,
  fatigueCost: 3, sfr: 3,
  subregion: 'hip_extension',                 // required where the muscle has
                                              // SUBREGION_REQUIREMENTS, else null
  aliases: ['One-Arm Kettlebell Swing', 'Single Arm KB Swing'],
  loadCharacter: 'ballistic',                 // 'grind' default
  overrides: {                                // optional, each key optional
    laterality: 'unilateral',
    difficulty: 2,
    exerciseType: 'weight_reps',
    loadSemantics: 'total',
    machineType: null,
    demands: { gripDemand: 'bar', unilateralLoadable: true },
  },
  cue: 'Hinge, not squat. Snap the hips and let the bell float to chest height. Keep the free hand clear of the bell.',
}
```
Rules: `name` never changes once shipped; `aliases` unique across the
whole corpus and never equal to any canonical name; `overrides` only
where the derivation is wrong or null for that row; `cue` 40 to 240
characters, British English, no em dash, no words from the banned list
(safe, injury, rehab, arthritis, pain, doctor, physio, therapy, medical,
condition), sentences end with full stops.

## 3. Mapping (corpusEntryToSeedRow)

Produces the object `rowToExercise` in `seedExercises.js` builds today,
in this order: base fields from the entry; `deriveExerciseMetadata`;
`deriveDemandMetadata`; `deriveLoadSemantics`; `movementFamily`;
adapted-setup class; then `overrides` applied last (each key validated
against vocab); then `exercise_category` = compound ? 'compound' :
'isolation'; `increment_kg` = the value the live screen's isolation-aware
increment expects (read `src/lib/algorithms.js` around the isolation
increment logic and pick values consistent with it: compound 2.5,
isolation 1.25, dumbbell or kettlebell isolation 1.0); `aliases` as a
JSON string; `load_character`; `cue`; `canonical id` from the name.

## 4. Seed flow changes (`seedExercises.js`)

- `RAW`, `SUBREGION_MAP`, `EXERCISE_TYPE_MAP`, `SINGLE_IMPLEMENT_TOTAL`,
  `ASSISTED_NAMES` and every other seed-local name map are removed; their
  content lives in the entries (generated by the conversion script).
- `seedExercisesIfNeeded` inserts `CORPUS.map(corpusEntryToSeedRow)` in
  one transaction (measure: 1,500 rows must insert in well under a
  second on device; batch the INSERTs).
- `topUpNewExercisesIfNeeded` (bump `LIBRARY_VERSION_KEY` to v4): for
  every corpus entry whose canonical id is absent: if a non-custom row
  with the same name (case-insensitive) exists under another id, re-id it
  to the canonical id rewriting `routine_exercises`, `workout_sets`,
  `exercise_user_notes`, `exercise_goals`, `exercise_swaps`, exclusions
  and any other referencing table, else insert. The exact precedent is
  the sync pull's same-name merge in `src/lib/database.js` (search
  `sameName` near the exercises upsert, around line 10380): it rewrites
  `routine_exercises`, `workout_sets`, `exercise_user_notes`,
  `exercise_goals` and the intent tables via
  `remapExerciseIdInIntentTables`, then deletes the duplicate row.
  Extract that into one shared helper and call it from both places.
  Today's top-up matches by id only (`seedExercises.js` ~1475), which is
  exactly why the eighteen template rows would duplicate by name.
- `rederiveExerciseMetadataIfNeeded` (bump `METADATA_REDERIVE_KEY` to v3):
  rewrite every derived column plus `aliases`, `load_character`, `cue`,
  `exercise_category`, `increment_kg`, `equipment` (for rows whose coarse
  equipment changed, e.g. band rows previously tagged bodyweight).
- `seedRoutines.js` `REQUIRED_EXERCISES` is deleted; its rows are corpus
  entries; the routine seed resolves names through the corpus.

## 5. Database (local, additive, `PRAGMA user_version` bump)

`ALTER TABLE exercises ADD COLUMN aliases TEXT`,
`ALTER TABLE exercises ADD COLUMN load_character TEXT`
(header note: purpose, applied locally, safe to re-run, rollback =
ignore columns). Not synced; not pushed for canonical rows.
`ALTER TABLE routine_exercises ADD COLUMN group_kind TEXT`,
`ALTER TABLE routine_exercises ADD COLUMN round_rest_seconds INTEGER`
(circuits, EL-9; these two ARE synced through the routine_exercises
path, so the cloud table needs the same additive columns: write
`supabase/migrate_158_routine_exercise_groups.sql` but do NOT apply it;
the client must tolerate the columns being absent on the cloud until the
founder runs it, so the push omits them while a feature flag
`CIRCUITS_SYNC_COLUMNS` is false).
`ALTER TABLE workout_sets ADD COLUMN evidence_class TEXT` (EL-7; synced
through the sets path: same rule, `migrate_159_workout_set_evidence_class.sql`
written, not applied, push omits the column until the flag is on).

## 6. Guards (`scripts/exercise-library/validate-corpus.mjs`, wired into
`npm run release:audit` and a Jest suite)

Fail on: duplicate canonical names (case-insensitive, normalised);
alias collision with any name or another alias; any value outside vocab;
subregion null where the muscle has requirements; secondary containing
the primary; inverted or absurd rep ranges; fatigue/sfr outside 1 to 5;
any name absent from the tier registry (`canonicality.js` gains an
explicit SPECIALIST list so unlisted is an error, while the runtime
default stays SPECIALIST); any demand axis null after derivation and
overrides unless the entry carries `unknownAxes: ['axis']` with a reason
string (the coverage report lists them); adapted-setup class missing;
cue rules; every name referenced by `CURATED_DEMANDS`, `ADAPTED_SETUP`,
`MACHINE_TYPE_BY_NAME`, `FAMILY_LISTS`, the tier registry and the
library plans existing in the corpus; the corpus count never decreasing
below the committed floor in `data/corpus-floor.json`; no orphan
exercise ids in seed routines.
