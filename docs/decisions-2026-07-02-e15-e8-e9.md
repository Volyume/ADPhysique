## E12 steps 0-1 execution rulings (2026-07-03, hands-on)

Founder GO covered E12 steps 0-1 (memo docs/e12-sync-consolidation-memo-
2026-07-03.md, Option C approved). Two design rulings taken while executing
step 1 — overrule if disagreed:

1. **migrate_094 tolerance for the sex mirror.** Moving `sex` into the
   registry profiles handler naively would make the WHOLE profile push/pull
   fail on the production project until the founder applies migrate_094
   (still outstanding). The handler therefore retries the upsert sex-less
   on error and falls back to the proven sex-less select on read — the
   exact pattern restoreSessionFromCloud already uses. Once 094 is applied
   the mirror sticks automatically; no second code change needed. Sex also
   NEVER unsets on pull (it drives the ED calorie floor + BMR): only a
   valid cloud value ('male'/'female') can change the local one.
2. **is_beta_tester write retired with syncProfile.** The only writer of
   the soft beta tag was the legacy syncProfile call inside the dormant
   PRO_BETA_ACTIVE path (locked false). The beta window is over; tier was
   always server-owned. If the tag is ever needed again it wants its own
   deliberate write path.

Mechanics shipped: per-save pushes for users_profile / weekly_checkins_v2 /
body_metrics now go through syncAll({triggeredBy:'write'}) — the spec'd
write trigger, previously unwired — at saveLocalProfile, ProUpgradeScreen,
saveWeeklyCheckin and BodyMetricsScreen. The runner's Article 9 gate now
covers these pushes too (it skips for a not-yet-consented user; the consent
grant kicks the sync that carries the data). Residual queued 'check_in' /
'body_metric' retry ops from older builds drain via the existing syncQueue
bulk fallback.
