10. Where the docs are wrong

Items that BACKLOG.md or CURRENT_STATUS.md claim are shipped, but where the code disagrees. Founder has explicitly flagged that these docs drift; this section is the code-truth correction.

Myo-rep / rest-pause cluster banner

BACKLOG claim: "Both set types exposed in the set type picker with descriptions, cluster banner shows activation set + mini-set counter, and a 'Cluster complete' button returns the user to straight working sets."

Code reality: SET_TYPE_OPTIONS in ActiveWorkoutScreen.js:62 only contains straight + warmup. myo_reps / rest_pause are recognised by display logic but cannot be picked by the user. Searching for "Cluster" / "activation" / "mini-set" / "Cluster complete" in src/screens/ + src/components/ returns zero rendered UI. Only a single // Cluster counter comment exists at ActiveWorkoutScreen.js:165.

Per-set RIR / RPE picker

BACKLOG / CURRENT_STATUS suggest: Per-set effort capture as a future addition.

Code reality: SetEntry.js:173–176 explicitly states the picker was built, found rarely used, and deliberately removed. The RIR field is still recorded internally (defaulted to 2 in DEFAULT_SET) so the autoregulation engine continues to work. Adding it back is reverting a deliberate UX decision, not closing a gap.

Peak Week module

CURRENT_STATUS § 8 OUT OF SCOPE claim: "Peak Week module (founder removed 2026-05-25: 'needs a human eye, not numbers')."

Code reality: peak_week_plans SQLite table exists with show_date, federation, current_bodyweight, lean_estimate, prep_carbs_per_kg, prep_sodium_mg, prep_water_l, status. peak_week_plans is in the cloud sync registry. phaseEngine.js:38 emits peak_week phase when within threshold. nutritionEngine.js integrates phase. So the data layer + phase awareness are built; what was removed is the algorithmic prescription / UI surface. Both interpretations are consistent. The founder's reasoning ("needs a human eye, not numbers") is sound: peak week is irreducibly a visual judgment under daily real-time adjustment, not something an algorithm can prescribe responsibly. The data layer remaining is harmless.

"Refeed automation"

BACKLOG status: "Scheduled refeeds (weekly) deferred."

Code reality: nutritionEngine.js:773–829 emits a refeedRecommendation object with maintenance kcal + recomputed protein / fat / carbs for aggressive_cut and physique_competition phases. The engine has it. What's missing is the UI surface that lets a user one-tap apply it.

FatigueTrendCard placement

BACKLOG claim: "FatigueTrendCard on HomeScreen renders an SVG bar chart of the last 6 sessions' fatigue levels."

Code reality: Renders in AnalyticsScreen.js:517, not HomeScreen. Cosmetic disagreement only.
